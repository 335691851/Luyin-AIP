# ERP数据补充与联调要求

本轮平台只读取ERP，不向ERP植入模拟库存或生产计划。请ERP维护方按下述契约补充数据；模拟业务记录须在ERP端明确标记。

## 1. 成品尾货处理

现有读取关系：`company → stock_balance → material/uom/lot`，并以 `stock_transaction` 的同公司、物料、批次正向流水取得最早可查入库日。

|ERP表|必须填写的字段|要求|
|---|---|---|
|company|id、name、kind|工厂为生产法人；合资公司为营销法人，必须保留真实法人ID|
|material|id、name、kind、uom_id|kind='product'；单位关联uom.name='吨'|
|lot|id、company_id、material_id、lot_no|批次所属法人、物料与余额一致；不可仅填写生产日期代替入库日|
|stock_balance|company_id、warehouse_id、material_id、lot_id、qty、reserved_qty|按公司/物料/批次合计实物余额；非负占用且不大于实物量|
|stock_transaction|company_id、material_id、lot_id、posted_on、qty_delta、line_id|必须保留完整历史入库；正向入库qty_delta>0，日期可转换为date|

固定筛选：检查日按上海时区当前日；截止日为检查日向前3个自然月；最早入库日**严格早于**截止日；同公司、物料、批次合计 `0 < qty < 0.5吨`。不是每个仓位分别小于0.5吨就命中。

例如检查日2026-11-05，最早入库2026-08-04、余额0.32吨应命中；2026-08-05不属于“超过3个月”；0.5吨、0吨均不命中。应提供至少两家工厂和鲁盐泰安的可验证批次，以及边界反例。不得把整批数量人为拆小来制造尾货。

当前余额表无快照日、冻结质量状态和货权字段，因此平台只能给出“待核实候选”。建议ERP补充库存快照日、可销售/冻结/待检量、货权及有效期。字段完成后再扩展映射，不能用“无候选”认定库存健康。

## 2. 工厂备货计划：平台已兼容的只读输入视图

由ERP维护方创建并授权 `public.ai_restock_plan_input` 视图。每行唯一粒度：**工厂法人＋成品物料＋计划起止日**，统一吨制。

|列名|类型|含义|
|---|---|---|
|company_id|integer|工厂法人ID，company.kind='生产法人'|
|material_id|integer|ERP成品物料ID，uom.name='吨'|
|plan_start / plan_end|date|计划窗口，开始日不晚于结束日|
|demand_qty|numeric|已确认、尚未履行的净需求，明确避免预测与客户订单重复计入|
|available_qty|numeric|相同快照日的实物减冻结、预留后的可用库存|
|in_transit_qty|numeric|预计计划结束日前可到达、可用于该需求的确定在途量|
|scheduled_qty|numeric|已下达且将在计划结束日前完工的有效成品量，不含在途|
|safety_qty|numeric|经批准的安全库存目标；若不使用，业务确认后明确填0|
|capacity_qty|numeric|该窗口尚未被其他计划占用的可生产能力|
|snapshot_date|date|以上数据统一快照日；必须为检查日或前一日|
|source_refs|text|需求计划号、在途单号、生产计划号、产能依据及算法版本索引|

计算：净缺口 `max(需求＋安全库存－可用－确定在途－已排产,0)`；建议新增备货 `min(净缺口,可用产能)`；剩余缺口单列。数字必须非负、非空，不得用未知值冒充0。多行视图不能重复同一粒度。过期快照不生成当前计划。

示例：需求100吨、安全10吨、可用20吨、在途15吨、已排产25吨，净缺口50吨；可用产能40吨，建议新增40吨，仍有10吨待协调。另一行库存足够则不产生计划建议。提供至少一个正常案例、一个产能不足案例、一个无缺口反例。

注意：现有 `demand` 单据在源库中可能为采购链需求，不能未经确认直接当成品销售需求；必须由ERP给出供货工厂、未交量与计划窗口的业务映射。

## 3. 已落实的订单名义利润

按已审核/已记账/已关闭的销售订单（document.type_code='sales_order'）及自然月统计。

- 行收入 = document_line.net_cents ÷ 100。
- 行名义成本 = document_line.cost_cents ÷ 100，直接使用ERP已有总成本，不做费用分摊。
- 行名义利润 = 行收入－行名义成本；订单成本、利润为所属明细求和；利润率为利润合计÷收入合计。
- cost_cents>0视为有效成本；零成本目前无法区分未维护和免费成本，保留“缺失”并展示覆盖率，不虚构利润。
- 分别汇总产品、法人和订单；各法人独立口径，包含内部交易，不是合并抵销后的集团会计利润。
- 2026-10核对基准：504行，收入7,022,060.55元，成本5,627,325.87元，名义利润1,394,734.68元。

## 4. 集团合同与账务核查的后续补齐

现有可读：sales_contract、contract_customer、contract_attachment、document/document_link、voucher/voucher_line。平台只检查集团法人ID=1，不将下级公司合同台账混入。

年度覆盖候选按同法人、客户、approved状态、覆盖自然年起止日匹配。当前kind仅有goods/service/mixed，缺少正式/框架标识，以及订单对合同的明确绑定；因此“匹配候选”不等于已正式覆盖。

请ERP增加或提供映射：合同性质formal/framework、自然年、订单合同ID、合同适用SKU/分类、签署原件状态、内部凭证来源链及会计科目对应规则。原件文件需要有受控下载接口，不能只有object_key字符串。未形成应收单的订单不判断为缺少记账凭证。

## 5. 最小权限与验收

ERP连接账号仅SELECT上述读取对象（包括新增只读视图），无需INSERT/UPDATE/DDL。平台记录、上传材料及模拟治理/调价批次只写platform。请先在ERP内验证每条样例的数量、单位、日期和来源编号，再在平台选择对应公司并重新计算。
