# ERP数据补充与联调要求

本轮平台只读取ERP，不向ERP植入模拟库存或生产计划。请ERP维护方按下述契约补充数据；模拟业务记录须在ERP端明确标记。

## 0. 可直接交给ERP开发人员的任务单

**目标：让产销协同的三类建议有可解释、可计算、可办理的ERP样例，不在平台前端写死卡片。**

2026-11-05按当前线上ERP全公司范围只读核查：

|模块|当前检查结果|ERP需要完成的工作|
|---|---|---|
|成品尾库清理|小于0.5吨且大于0的批次汇总余额为0组，因此尾库候选为0|补齐有完整入出库历史的真实尾量批次，首批6个命中场景及边界反例|
|库存销售计划|按当前规则有104个公司＋物料组合命中|已有数据，不需要盲目加库存；补充6组可复核的差异化场景、来源单据和新近流水|
|工厂备货计划|`public.ai_restock_plan_input`不存在|ERP新增12列只读视图，以已确认需求、可用库存、在途、已排产和剩余产能输出计划输入；首批6个有效场景|

当前最新销售订单、库存流水日期均为2026-10-26。这里的“最新流水”不是库存快照，不能据此证明余额已更新到当天。上述104组为源规则命中数，页面每类最多返回100条；已“同意/否决”的建议会移到处理记录，不能把待处理列表数量直接当成源库命中数。

**交付范围：**至少覆盖2家工厂、鲁盐泰安和另1家合资公司，选用至少3种成品；每条样例有稳定场景编号、ERP单据号、批次或计划窗口、计算值及预期结果。首批18个命中场景，加以下反例用于验收，不要求堆积大量同质记录。

当前可用法人ID：2山东菜央子盐场、3山东寒亭第一盐场、4山东肥城精制盐厂、5山东岱岳制盐，均为`生产法人`；7鲁盐泰安、8鲁盐鲁南、9鲁盐鲁中、10鲁盐潍坊、11鲁盐济宁、12鲁盐滕州及6鲁盐集团菏泽为`营销法人`。ID=1为集团总部，不用作工厂备货主体。最终以ERP公司主数据为准。

### 样例数据的共通约束

- 优先通过ERP正常业务单据及过账机制生成订单、流水和余额，不只直接改库存余额。入库、出库、调拨等依ERP自身规则生成有效`line_id`和唯一`posting_key`，不得重复过账。
- 有`document`单据的样例必须设置`is_simulated=true`，单据号/批次号使用`SIM-AIP-`前缀，`memo`或视图`source_refs`写明“联调模拟＋场景编号”。不得把模拟单据改标为真实业务。
- 优先使用测试账套或独立模拟SKU。当前平台不会自动排除`is_simulated=true`的订单，因此在当前线上库新增样例订单也会影响业务数据、名义利润报表。请ERP维护方先确认使用范围，不改写既有真实业务记录。
- 同一法人＋物料的清库计算会合并全部仓库和批次。推荐为不同清库场景使用独立模拟SKU；若复用已有SKU，必须把原有库存与最近30日订单一起计算，不能只看新插入的几行。尾库场景则按同法人＋物料＋批次合并所有仓库。
- 物料`kind='product'`，数量统一为吨；包装“500g/袋、25kg/袋”只是规格，100袋×25kg应填写2.5吨。不得将袋数、千克数直接填进吨制字段。
- 法人、仓库、物料、批次、订单行和流水必须归属一致。不能把集团内部销售订单、合资公司对外订单混加到同一家公司的需求中，也不能将某工厂所有权以外的库存作为本厂可用量。
- 日期使用可排序的ISO格式`YYYY-MM-DD`，不要写`2026/8/5`等格式。当前部分ERP日期列为字符串，平台依赖标准格式计算或排序。

以下统一用`D`表示实际联调当天的上海日期，`C`表示`D`向前3个自然月。样例应按实际联调日重算，不能长期固定使用本文件中的示例日期。

## 1. 成品尾货处理

现有读取关系：`company → stock_balance → material/uom/lot`，并以 `stock_transaction` 的同公司、物料、批次正向流水取得最早可查入库日。

|ERP表|必须填写的字段|要求|
|---|---|---|
|company|id、name、kind|工厂为生产法人；合资公司为营销法人，必须保留真实法人ID|
|material|id、name、kind、uom_id|kind='product'；单位关联uom.name='吨'|
|lot|id、company_id、material_id、lot_no|批次所属法人、物料与余额一致；不可仅填写生产日期代替入库日|
|stock_balance|company_id、warehouse_id、material_id、lot_id、qty、reserved_qty|按公司/物料/批次合计实物余额；非负占用且不大于实物量|
|stock_transaction|company_id、material_id、lot_id、posted_on、qty_delta、line_id|必须保留完整历史入库；正向入库qty_delta>0，日期可转换为date|

固定筛选：检查日按上海时区当前日；截止日为检查日向前3个自然月；最早入库日**严格早于**截止日；同公司、物料、批次合计 `0 < qty < 0.5吨`。不是每个仓位分别小于0.5吨就命中。

例如检查日2026-11-05，最早入库2026-08-04、余额0.32吨应命中；2026-08-05不属于“超过3个月”；0.5吨、0吨均不命中。应提供至少两家工厂和鲁盐泰安的可验证批次，以及边界反例。不得把整批数量人为拆小来制造尾货。

当前余额表无快照日、冻结质量状态和货权字段，因此平台只能给出“待核实候选”。建议ERP补充库存快照日、可销售/冻结/待检量、货权及有效期。字段完成后再扩展映射，不能用“无候选”认定库存健康。

## 2. 工厂备货计划：平台已兼容的只读输入视图

由ERP维护方创建并授权 `public.ai_restock_plan_input` 视图。每行唯一粒度：**工厂法人＋成品物料＋计划起止日**，统一吨制。

|列名|类型|含义|
|---|---|---|
|company_id|integer|工厂法人ID，company.kind='生产法人'|
|material_id|integer|ERP成品物料ID，uom.name='吨'|
|plan_start / plan_end|date|计划窗口，开始日不晚于结束日|
|demand_qty|numeric|计划窗口内已确认、未交且尚未被本次需求预留库存覆盖的净需求；不要再扣在途和已排产|
|available_qty|numeric|相同快照日的实物减冻结、预留后的可用库存|
|in_transit_qty|numeric|预计计划结束日前可到达、可用于该需求的确定在途量|
|scheduled_qty|numeric|已下达且将在计划结束日前完工的有效成品量，不含在途|
|safety_qty|numeric|经批准的安全库存目标；若不使用，业务确认后明确填0|
|capacity_qty|numeric|该窗口尚未被其他计划占用的可生产能力|
|snapshot_date|date|以上数据统一快照日；必须为检查日或前一日|
|source_refs|text|需求计划号、在途单号、生产计划号、产能依据及算法版本索引|

计算：净缺口 `max(需求＋安全库存－可用－确定在途－已排产,0)`；建议新增备货 `min(净缺口,可用产能)`；剩余缺口单列。数字必须非负、非空，不得用未知值冒充0。多行视图不能重复同一粒度。过期快照不生成当前计划。

示例：需求100吨、安全10吨、可用20吨、在途15吨、已排产25吨，净缺口50吨；可用产能40吨，建议新增40吨，仍有10吨待协调。另一行库存足够则不产生计划建议。提供至少一个正常案例、一个产能不足案例、一个无缺口反例。

注意：现有 `demand` 单据在源库中可能为采购链需求，不能未经确认直接当成品销售需求；必须由ERP给出供货工厂、未交量与计划窗口的业务映射。

### 备货输入口径：重点避免重复扣减

1. ERP必须能追溯“需求单/订单行 → 供货工厂 → 成品物料 → 交付日期 → 尚未交付量”。这不是把营销公司的历史销量直接填成工厂需求；首期不要求做销量预测。
2. 因为`available_qty`已经扣除预留量，`demand_qty`必须扣掉**这部分需求已经被预留库存覆盖的量**。例：订单未交100吨、其中60吨已有库存预留；实物80吨、扣预留后可用20吨，则视图填`demand_qty=40、available_qty=20`，净缺口20吨。不能填100与20，否则同一预留量被重复计算，虚增缺口60吨。
3. 在途、已排产仍在公式中单独抵减，不应提前从`demand_qty`再扣一次。只计入计划结束前能到达/完工且尚未转现存库存的有效数量，取消或逾期部分不计入；同一来源不得同时算在途和已排产。
4. `capacity_qty`是扣除已有计划占用后的**剩余**可生产能力，不是工厂总产能。须确认本厂确实能生产该SKU；同一库存/需求不能在多个重叠计划窗口重复生成建议。首期每个工厂＋SKU在同一快照下仅输出一个有效计划窗口。
5. `source_refs`虽然是text列，但应写清楚可定位的单据/行号及计算依据。例如：`模拟样例R01；未交订单SIM-AIP-SO-001/1；预留RES-001；在途TR-001；已排产MO-001；产能日历CAP-001；口径v1`。仅填“测试”“AI估计”不能通过业务验收。
6. `plan_start`建议为D，`plan_end`为D+14天，`snapshot_date`为D；当前代码也接受D-1的快照。每天滚动重算快照和窗口；不能只改日期、不更新需求与库存。未知量填null并补齐依据，不用0掩盖缺数；确实不采用安全库存时，经业务确认后才填0。

## 3. 库存销售计划：需要补齐的订单与库存场景

现有读取：`stock_balance`按**公司＋物料**合并全部仓库与批次；`document/document_line`读取该公司同物料最近30日审核订单。

|对象|必填字段/条件|说明|
|---|---|---|
|document|company_id、type_code、bill_no、bill_date、status、is_simulated、memo|type_code='sales_order'；纳入状态仅approved/posted/closed|
|document_line|document_id、line_no、material_id、qty及ERP必需金额字段|qty为吨；金额和成本按ERP正常计算，保持单据头行一致|
|stock_balance|company_id、material_id、qty、reserved_qty，以及有效仓库/批次|实物与占用不混淆；不得以占用值替代冻结、待检等不同业务状态|
|关联与过账|真实业务链允许的订单/出库/流水关系|订单量用于动销分析，不等于已发出量，更不是备货视图的净需求|

近30日窗口为`[D-30天,D)`，含起日、不含检查当天。以2026-11-05为例，统计2026-10-06至2026-11-04，不是“上一个自然月”。

当前计算：`A=max(实物P－占用R,0)`，`Q=近30日纳入状态的订单量合计`。A>0，且Q≤0或A>2×Q时，产生库存核查候选；Q>0时覆盖天数=`A÷Q×30`。60天为当前**试运行分析参数**，不是已经正式确认的经营红线。

|编号|主体示例|实物P|占用R|近30日订单Q|预期|
|---|---|---:|---:|---:|---|
|C01|鲁盐泰安7|120|20|30|A=100，覆盖100天，命中|
|C02|鲁盐鲁南8|80|0|0|有可用库存但无近期订单，命中；不能计算覆盖天数|
|C03|鲁盐集团菏泽6|55|5|20|A=50，覆盖75天，命中|
|C04|工厂5|500|100|100|A=400，覆盖120天，命中|
|C05|工厂4|150|0|50|覆盖90天，命中|
|C06|鲁盐滕州12|12|2|1|A=10，覆盖300天，命中|
|C07|任一上述公司|120|20|50|恰好60天，不命中|
|C08|任一上述公司|35|5|20|45天，不命中|
|C09|任一上述公司|20|20|0|全部占用，A=0，不命中|

另提供日期/状态边界：D当天订单不纳入；D-30当天纳入；D-31不纳入；draft/cancelled等非上述纳入状态不纳入。不同场景不要复用同一公司＋SKU，否则数据会被合并，无法按本表逐行验算。

目前没有正式销售目标、渠道需求、可销售/冻结量映射，平台只能生成“库存销售计划核查建议”，不能据此承诺可销售量、推荐特定客户或自动调价。额外补充这些字段后还需平台增加映射，单独新增字段不会自动改变现有算法。

## 4. 已落实的订单名义利润

按已审核/已记账/已关闭的销售订单（document.type_code='sales_order'）及自然月统计。

- 行收入 = document_line.net_cents ÷ 100。
- 行名义成本 = document_line.cost_cents ÷ 100，直接使用ERP已有总成本，不做费用分摊。
- 行名义利润 = 行收入－行名义成本；订单成本、利润为所属明细求和；利润率为利润合计÷收入合计。
- cost_cents>0视为有效成本；零成本目前无法区分未维护和免费成本，保留“缺失”并展示覆盖率，不虚构利润。
- 分别汇总产品、法人和订单；各法人独立口径，包含内部交易，不是合并抵销后的集团会计利润。
- 2026-10核对基准：504行，收入7,022,060.55元，成本5,627,325.87元，名义利润1,394,734.68元。

## 5. 集团合同与账务核查的后续补齐

现有可读：sales_contract、contract_customer、contract_attachment、document/document_link、voucher/voucher_line。平台只检查集团法人ID=1，不将下级公司合同台账混入。

年度覆盖候选按同法人、客户、approved状态、覆盖自然年起止日匹配。当前kind仅有goods/service/mixed，缺少正式/框架标识，以及订单对合同的明确绑定；因此“匹配候选”不等于已正式覆盖。

请ERP增加或提供映射：合同性质formal/framework、自然年、订单合同ID、合同适用SKU/分类、签署原件状态、内部凭证来源链及会计科目对应规则。原件文件需要有受控下载接口，不能只有object_key字符串。未形成应收单的订单不判断为缺少记账凭证。

## 6. 最小权限与验收

ERP连接账号仅SELECT上述读取对象（包括新增只读视图），无需INSERT/UPDATE/DDL。平台记录、上传材料及模拟治理/调价批次只写platform。请先在ERP内验证每条样例的数量、单位、日期和来源编号，再在平台选择对应公司并重新计算。

### ERP完成后请交回的验收清单

1. 一张场景清单：场景编号、模拟标识、法人ID、物料ID、仓库ID、批次/窗口、相关单据号及行号、快照日、最终输入数值、预期是否命中及计算结果。必须给最终ID，不能只说“已加一些数据”。
2. 尾库：给出T01—T11对应的批次合计和最早正向入库证据；库存销售计划：给出C01—C09的P/R/Q及窗口；备货：给出R01—R11的视图查询结果和来源索引。
3. 对新增视图给当前`ERP_READONLY_DATABASE_URL`对应账号授予SELECT；确认该账号能看见12列并查询实际数据，不需要新建外部API、消息队列或模型服务，也不需要将ERP写权限交给本平台。
4. 联调当天选择具体公司、清空搜索后“重新计算”。本平台应能展示命中建议、证据数字、公式与AI核查意见，并完成“同意/否决/待定”和处理记录的保存；这些操作只保存平台决策，不自动生成ERP销售、调拨或生产单。
5. 若当前列表为空，先检查：公司授权与筛选、吨制/成品分类、批次跨仓总量、入库日是否严格早于C、订单日期/状态、视图列名、工厂类型、快照时效、重复窗口、来源是否为空，最后检查该建议是否已经进入处理记录。
