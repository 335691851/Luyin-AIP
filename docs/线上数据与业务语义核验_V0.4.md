# 鲁银智能化平台线上数据与业务语义核验

版本：V0.4｜核验日期：2026-11-04（Asia/Shanghai）｜用途：为PRD及功能拆解提供可复查的数据依据。

本轮直接使用本地配置的线上ERP Postgres和OntoRAG REST/MCP读取数据。ERP查询使用READ ONLY事务与语句超时；图谱只执行元数据读取和SELECT。未修改ERP、图谱、制度文件或线上业务记录。原始结构与查询响应保存在被Git忽略的.local/semantic-inspection目录；本文保留聚合结果和必要的出处标识，不保存连接串、服务密钥、客户名单或PDF全文。

## 1 核验结论

ERP已经具备订单成本、部门、销售大区、内部交易链、库存流水和历史特殊价格等语义，首期不必把这些能力全部退回人工填报。需要先建立稳定的指标定义和关联规则，再生成报表与辅助判断。

线上部署不等于经营记录已经核实真实。当前300,000张交易单据均标记is_simulated=true；1,200条调价历史也均标记为模拟，1,000份合同表单均带模拟说明。这些数据可以驱动真实计算与功能联调，但不能在页面、报告或AI回答中被描述为企业真实业绩。平台功能是否真正运行与来源数据是否为模拟是两个独立属性。

OntoRAG可用于发现制度要求、职责、流程和原文锚点；目前还不能把图谱中的每个节点直接当成已发布检查规则或已发生的企业风险。

## 5 业务语义决策

1. 订单金额以document_line.net_cents为准；每次统计先选定销售订单，再在订单行粒度聚合，防止文档链与附件连接放大金额。
2. 首期名义利润优先采用已验证的订单成本快照；用cost_cents/qty展示单位成本，计算总成本仍保留源分值。尚未发布该财务口径时可验算并明确标记，不能静默变为正式口径。
3. 销售大区取sales_terms.sales_group，收货地区取ship_to；没有行政区编码时不声称已完成省市标准化。集团营销部门通过employee.department_id和sales_terms核对，区域法人不合并为部门。
4. 历史专项调价价、实际成交均价、目录价、合同价、内部结算价分别建语义对象。只有主体、SKU、币种、单位、税口径、运费、数量及适用范围可比时才允许直接比较。
5. 合同覆盖候选与覆盖已确认是两个状态；独立合同表单、交易单据合同、框架确认记录分别保存来源命名空间。
6. 图谱提供制度要求候选；平台管理真实业务事实、补正材料和复核结果；二者通过引用关联，不把制度概念当实际案件。
