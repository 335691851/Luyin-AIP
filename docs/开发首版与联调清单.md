## 二、核心页面的二级、三级功能与价值

下列为需要实现的目标功能，不能仅以按钮存在作为完成依据。沿用既定简易后台，不引入复杂组织流程引擎。

### 2.1 主题报表

|二级功能|三级功能|价值与验收条件|
|---|---|---|
|固定报表目录|法人月报、产品分类、区域、日趋势；模板说明与口径版本|默认展示完整报表，多表头表格占主要面积，饼图/柱状图辅助；不以查询表单代替报表|
|期间与范围|自然月、法人、产品分类筛选；本月/上月切换|每次变更重新查询授权数据，禁止使用最近N行代表完整期间|
|结构与比较|销售额/销量占比、同比/环比、排名、变化额|销售按订单；数量仅统一单位后汇总；无同期基数显示不可计算，不能除零|
|明细追溯|汇总单元格下钻订单行、订单号/状态/业务日/物料编码|下钻结果与汇总可对账；未映射分类仍保留在总额中|
|数据质量|刷新时间、源记录数、缺失映射数量、单位分布|能区分无订单、无权限、数据源故障、映射不足；不能都显示0|

### 2.2 名义利润分析

|二级功能|三级功能|价值与验收条件|
|---|---|---|
|成本口径维护|法人×产品×单位×生效期间的有效单位成本/结算价；管理员确认|使用财务明确的简单口径，不分摊费用；有效期不得重叠；不把销售标价当成本|
|订单行计算|订单净额－订单数量×有效单位成本；利润率；成本来源|订单行可追溯到生效规则，缺成本显示待补充，收入为0时利润率为空|
|固定分析报表|产品利润贡献、法人利润对照、区域利润、低利润订单清单|同一指标提供不同分析视角；利润率按总利润/总收入计算，不平均各行比率|
|完整性管理|可计算收入占比、缺成本产品、规则失效项|不完整时区分已覆盖部分与完整总体，禁止输出误导性的整体排名|
|差异复核|成本版本切换、原值/新值、受影响订单、重算历史|修改规则后留下版本与重算记录；不覆盖历史审批所引用的证据快照|

### 2.3 每页智能问数抽屉

|二级功能|三级功能|价值与验收条件|
|---|---|---|
|上下文问数|继承页面期间/法人、显示本次查询范围、澄清歧义|用户说“上月”按上海当前自然日解析，不能直接沿用页面月份冒充理解|
|语义建模|业务名词/同义词、指标公式、单位、维度、表关联、日期/状态口径|管理员维护并发布版本；维护测试问题与预期结果，修改后回归；草稿不直接影响生产|
|NLP2SQL执行|模型产生受约束查询计划、编译参数化只读SQL、强制授权范围、超时与结果上限|模型不能自行取消法人/部门范围；拒绝写语句/非授权表；查询失败明确报错|
|结果呈现|数值解释、明细表/简单图、查询条件、来源、执行时间|回答中数字来自查询结果，不由模型心算补全；可展开经过脱敏的查询说明|

### 2.8 简易用户与角色管理

二级入口仅“用户”“角色权限”“语义模型”“连接”。用户支持真实账号绑定/停用、单角色、法人范围、可选部门范围；角色映射查看/导出/申请/审核/管理权限。上级监管权通过显式授权法人集合表达，不以树节点自动授予所有权限。仅鲁盐管理员审核；用户停用和权限变更应在后端立即生效。

本地角色预览用于检查不同视角；正式角色预览如需启用，必须是管理员的显式只读预览并可一键退出，不允许通过可修改Cookie冒充真实用户执行审批。实际提交记录真实操作者身份。

## 三、运行底座与数据库落地

- Next.js + TypeScript；前端保留当前鲁盐红主题与报表布局；Vercel部署。
- LangChain作为智能体底座；DeepSeek Flash负责解析/评估/归纳。金额和数量由确定性SQL与Decimal计算，模型结论必须引用证据。
- ERP通过服务端Postgres连接读取。平台业务使用独立platform schema与写入角色，同项目可部署；不写ERP业务表。
- Supabase Auth负责真实身份。权限来源数据库，不把本地预览目录作为正式用户目录。
- 平台需落地：成员/角色范围、语义版本、简单成本规则、申请批次/行/行版本/审核记录、附件元数据、分析任务/证据快照、建议反馈、合同扫描/风险、治理事项/制度范围/整改、审计事件。
- 写操作采用服务端授权+事务+版本号+幂等键；附件只存私有Storage并按当前权限发短期链接；浏览器localStorage不得作为正式业务存储。
- 长任务需有数据库任务状态、超时、重试次数和失败原因；仅内存Promise不能视为可靠后台任务。先确定数据规模再选择异步运行机制，不提前堆叠复杂基础设施。
- ERP现有成本、签约、库存日期与权限字段需逐项映射。字段不存在时建立平台确认数据，不编造ERP字段；流程应允许人工补充真实依据。

## 四、开发顺序与明确验收

1. 真实链路：数据库/模型/知识服务检测 → 成员授权 → 完整期间订单 → 与ERP同范围SQL对账 → 简单成本规则与利润复核。
2. 首个智能体闭环：语义版本 → 查询计划与只读SQL → 真实DeepSeek调用 → 返回数字/图表/来源 → 反例与越权回归。
3. 首个审批闭环：批次上传校对 → 真实证据查询 → 整批智能评估 → 逐行审核 → 数据库存档 → 刷新/换浏览器后复核。
4. 再接库存建议、年度合同扫描、OntoRAG制度检查与治理整改。每项单独验收后才标记可用。

验收须包含：正常路径、无数据、缺字段、模型超时、数据库故障、跨法人越权、重复提交、并发修改、审批证据过期。测试样例可以虚构，但正式业务验收必须使用受控真实数据；浏览器页面能打开和构建通过不足以认定完成。

## 五、当前配置依赖

.env.local所需配置已于2026-11-04补齐，并经应用自身接口验证：ERP基础表可读、DeepSeek经LangChain返回真实响应、OntoRAG文档API鉴权通过。平台数据库授权结构已初始化，并为用户指定的现有Auth账号绑定超级用户权限；业务申请/审批等表仍待后续开发。当前ERP连接账号有写权限，不能当作已经具备数据库级只读隔离；查询仍强制只读事务，后续需创建专用受限角色。密钥只保存在本地文件，不发聊天。
