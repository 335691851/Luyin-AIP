# 业务迭代 V0.5（2026-11-05）

本说明替代早期文档中“仅支持排名问数、利润无成本、调价仅演示、治理只有统一台账且不能上传”的限制说明。

## 智能经营

- 数据洞察助手使用 LangChain / DeepSeek 生成 PostgreSQL SELECT，读取实际ERP表结构、物料编码/分类/单位/盐源/包装字典与关系。支持产品、法人、时间、库存、成本及获授权的合同/凭证主题，不限于前三/前五排名。
- 只读表范围由权限决定；公司范围通过服务器注入的作用域CTE隔离。模型不能直接引用public/auth/platform/系统目录；AST校验单语句、表、函数与类型，禁止锁与写操作；查询8秒超时、返回上限200行。模型SQL不等于经过财务审核的分析，保留实际查询口径及SQL供核对。
- 校验中文标识符格式，并拦截订单头与行关联时直接SUM订单头金额造成的重复汇总。失败时最多一次修正；超过范围或无法匹配字段时说明原因。
- 业务数据删除区域报表；利润删除区域分析，增加订单维度。订单行成本直接取cost_cents，不分摊费用。产品、法人、订单报表与图形共享同一汇总，成本与利润可追溯到订单行，导出同口径。
- 调价新建入口接通平台数据库：ERP产品选择、多行申请、XLSX字段读取与人工确认、整批AI评估、逐行审批、版本冲突检查和事件留痕。ERP原有1200条历史只读展示；另初始化21个明确标识的模拟批次，不执行ERP调价。
- 调价评估读取申请方近30日审核订单、申请方及授权工厂的同产品库存、可比历史。财务有效内部结算价、指定供货工厂映射和原件真实性未接入时明确缺项；不将申请价或历史价冒充财务结算价。
- 工厂备货“缺口”更名“计划”。尾货及备货输入要求见[ERP数据补充与联调要求](ERP数据补充与联调要求.md)。备货只读视图契约已兼容，未补齐数据时不捏造计划。

## 集团监管视角

1. **集团监管总览**：重要风险与提请集团审核的事项汇总，不将所有一般治理动作堆入监管台账。
2. **监管风险问题**：仅重要监管问题，含影响、证据、处置建议与办理历史；可要求整改或确认处置，整改关联在问题详情内，取消独立“整改督办”菜单。
3. **治理事项审核**：公司主动提请集团审核的治理事项，数据对象与重要风险分开。归档、退回、要求整改等人工结论留痕。
4. **集团合同风险**：集团法人ID=1的实际订单、年度合同候选、内部业务来源链、应收单、已记账凭证及借贷平衡核查。另保留3条不同合同账务模拟处置事项。候选合同未经过框架性质、SKU和签署原件核验，规则命中是核查线索，不自动认定违规。

## 公司治理与自查

默认公司为鲁盐泰安，服务端仍按已授权公司范围校验。

|模块|业务对象和关系|
|---|---|
|公司治理档案|只读章程、授权清单、重大事项与会议规则、合规自查规范；展示核心要求、版本和可下载的规范文件样例，不提供编辑/审批按钮|
|治理责任与授权|授权续期、岗位职责分离等具体管理动作；关联档案条款与材料要求|
|重大事项程序|议案、风险论证、权限判断和保留事项提请；与集团审核衔接|
|会议决议与履职|通知、出席、回避、表决、签署与落实材料的提交及审核|
|制度与合规自查|制度适用性、版本确认、自查底稿与缺项检查|
|问题整改|由审核退回/集团要求整改生成的子事项；关联原动作/风险、材料、责任人与期限，可提交整改并复核关闭|
|智能治理助手|独立聊天页面，结合公司关联档案与图谱检索，回答制度、规范、合规和治理问题，不显示经营数据洞察悬浮助手|

正常流程：档案基线 → 人工提交或智能体生成治理动作 → 上传材料 → 公司审核 → 归档；审核退回会自动生成关联整改；重要/保留事项提请集团审核，集团要求整改后公司反馈、集团验收。

治理材料单份最多2MiB、每事项10份，存于private platform表并由服务端按公司鉴权下载。TXT/MD提取文本供模型核查；PDF/DOCX/XLSX/图片目前保存原件，内容需人工核验，不声称已OCR或理解签章。

“按档案生成治理动作”实际调用模型，按公司、季度、治理领域幂等保存，不重复生成同季度同类动作。档案样例和图谱参考目录不等于正式有效的公司制度；需后续用正式版本替换并确认公司适用范围。

## 模拟数据与持久化

`scripts/seed-business-iteration.mjs`按稳定key初始化7家营销法人：每家4份档案、6项不同管理动作、1项关联整改、2项重要监管问题；加3项集团合同账务情景，共94条基线记录，另含28份可下载的模拟材料、21个三行调价批次。重复执行不覆盖已有用户办理结果。全部模拟数据明确标识，ERP源表与OntoRAG图谱不写入。

变更结构：`supabase/migrations/20261105042144_business_iteration.sql`，已应用当前项目。不要在Vercel构建中执行迁移或初始化脚本；新增环境先整理ERP与平台迁移历史。

验证脚本：`scripts/verify-business-iteration.mjs`。账号凭据仅由LIVE_TEST_EMAIL/LIVE_TEST_PASSWORD进程变量传入，不保存登录截图或token。脚本会创建带“联调模拟”标识的申请和治理闭环记录，只写platform；模型请求为真实调用。

## 本轮验证结果（2026-11-05）

### 年度概览增补

业务数据和名义利润分析的“报表范围”可切换“年度概览 / 月度报表”。年度默认本年，可选择近10个自然年；全年数据直接读取授权范围内的ERP订单，仍执行50,000行上限检查，超限拒绝而非截断。全年指标、12个月汇总、月度销售额/销量/名义利润折线、产品结构及明细共用同一份数据，可下载月度汇总CSV。利润指标按角色权限显示；无订单月保留为无数据，成本不完整不算利润，单位不统一不合并销量，负利润结构改用盈亏柱图。问数助手同步全年上下文。验证脚本：`scripts/verify-annual-report.mjs`。

### 数据洞察助手会话与图表增补

- 正式环境问答保存在`platform.insight_conversation / insight_message`，包含问题、筛选上下文、完整返回结果和查询口径；最近50个会话可选择，单会话按5条加载并支持读取更早记录。刷新、跨页面后可恢复；新建、删除会话均可用。历史数据按账号及有效角色、授权公司、权限快照隔离，权限变化后旧范围记录不再可读。上线前未保存的旧问答不能追溯恢复。
- 继续追问会参考本会话最近4轮的查询口径，仍执行现有只读SQL及法人授权校验。每条结果保留当时期间和公司范围，不以当前页面条件覆盖历史。
- Enter发送、Shift+Enter换行；中文输入选字时不发送，等待返回时防止重复提交。演示模式的记录仅存当前浏览器，与正式数据隔离。
- 表格分页受控，支持10/20/50/100行并在改变行数后回到第一页。图表可切换分组、指标与折线/条形/柱形/占比，使用本次完整返回结果，不再仅取前10行。按容器宽度和结果数量调整，长数据支持缩放；负值或缺失不做占比，重复金额分组求和，比率和均价保留明细，不盲目相加，数量单位混合时提示先筛选。
- 结构迁移`20261105083916_insight_history.sql`已应用当前项目；不写ERP。复核脚本`scripts/verify-insight.mjs`使用进程变量中的登录凭据，调用真实模型并验证持久化、权限隔离、历史分页及浏览器交互；结束后删除脚本自身创建的联调会话。
- `VERIFY_UI_ONLY=true`可使用明确标记的临时模拟结果验证界面交互，最后的回车发送仍调用真实模型。本次57项单元测试、2项鉴权测试、实际130行查询及12家公司追问、历史隔离/翻页、刷新恢复、每页行数、移动端SVG尺寸和输入法行为均已验证。

- 生产构建与TypeScript检查通过，47项单元测试、2项匿名访问与伪造权限测试通过。
- 实际ERP查询核对2026年10月504条订单行：收入7,022,060.55元、成本5,627,325.87元、名义利润1,394,734.68元、利润率19.86%。不分摊管理费用、运费等费用。
- 实际DeepSeek调用已验证跨法人利润查询、海盐产品销售查询、整批调价评估、按档案生成治理动作及治理问答；治理问答成功检索OntoRAG证据。
- 浏览器验证集团/公司视角切换、只读档案、移除区域报表，以及新建调价申请持久化。新建表单专项脚本为`scripts/verify-pricing-form.mjs`，使用相同进程凭据变量。
- 实际API验证逐行调价审核、版本冲突、治理材料上传、整改提交与验收、关联原事项关闭及审计事件保存。上述验证针对本地应用连接线上数据服务，不等同于Vercel部署后的回归验证。

登录请求采用Supabase签名JWT校验及JWKS缓存；角色、成员授权和公司范围仍在服务端读取有效数据库记录。经营页面仅加载所需报表数据，调价及产销协同不再额外发起无关报表查询。
